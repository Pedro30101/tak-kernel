# TAK Kernel 0.5.9

**Astros** is the graphical desktop environment built into the TAK Kernel. This repository contains an experimental x86-64 operating-system project that boots through GRUB/Multiboot2, loads its initial files from an initramfs, and starts either the live desktop or the installed-system login screen.

> **Project status:** experimental and unfinished. It is for development and testing, not for storing sensitive data or use as a secure, production operating system.

## What works today

- GRUB Multiboot2 boot, with BIOS/UEFI boot files assembled by the ISO build.
- A graphical desktop and window manager, keyboard/mouse input, terminal, settings, and file manager.
- A virtual filesystem populated from the initramfs, plus FAT32 and ATA/IDE support used by the installer and installed system.
- Kernel-managed tasks and a restricted `.te` user-program format.
- Built-in utilities and applications, including a text editor, TIDE Studio, image viewer, media player, task manager, settings, and installer.
- Framebuffer-based display support on systems with **Intel, AMD, and NVIDIA** graphics, as well as several virtual display adapters. The kernel identifies these vendors through PCI; drawing uses the framebuffer supplied by the bootloader, not vendor-specific 3D acceleration drivers.

### Networking and security limitations

Networking is **not implemented**. There are no active network drivers or packet-handling stack. The terminal's `net-info` command only lists PCI network adapters for diagnostics; it does not connect to a network or transmit packets.

Security is also **unfinished**. Do not treat the login screen, user-process isolation, or storage as a complete security boundary. The system is not intended to protect sensitive information or resist a hostile physical user.

## Version and wallpaper

The version shown by the current desktop, terminal, boot log, and default wallpaper comes from the `VER` macro in [`src/tak.h`](src/tak.h), currently `0.5.9`. Changing `TAK_VERSION` in `src/kernel.c` does **not** change those surfaces: it is a separate string used by the legacy VGA-console code in that file.

The default wallpaper is generated by the window manager in [`src/wm.c`](src/wm.c); its background and the small version label are separate from `TAK_VERSION`. Choosing a custom wallpaper changes the desktop image, not the kernel version. Rebuild the kernel and boot the rebuilt image to see source changes.

## Build and run

The build uses a GNU-compatible C toolchain targeting x86-64, GNU binutils, GRUB utilities, `xorriso`, and QEMU for emulation. The `make run` target launches QEMU; the ISO target also needs the GRUB BIOS/UEFI image-generation tools.

On Ubuntu or WSL, install the common build dependencies:

```sh
sudo apt update
sudo apt install build-essential gcc-x86-64-linux-gnu binutils-x86-64-linux-gnu \
  grub-common grub-pc-bin grub-efi-amd64-bin xorriso mtools qemu-system-x86
```

Build the kernel and bootable ISO from the repository root:

```sh
make CROSS=x86_64-linux-gnu- iso
```

The ISO is written to `build/astros.iso`. To build and boot it in QEMU:

```sh
make CROSS=x86_64-linux-gnu- run
```

The build can also be opened and edited in VS Code while using WSL as the Linux build environment. The Windows GitHub website is useful for viewing and editing files, but compiling and booting the OS requires a local toolchain or another configured build environment.

## Editing the kernel

1. Open the repository root in VS Code (or edit the source through the GitHub website).
2. Make kernel changes in the relevant files under `src/`. For example, kernel-wide definitions live in `src/tak.h`, startup is in `src/kmain.c`, the window manager is in `src/wm.c`, and task/process code is in `src/proc.c`.
3. Keep declarations in the matching headers and follow the existing freestanding C patterns. The kernel is built with warnings treated as errors (`-Werror`).
4. Rebuild the ISO using the command above, then boot it in QEMU before testing on physical hardware. Changes to boot, disk, or installer code should be tested especially carefully; installer operations can modify disks.
5. If changing a user application, edit its source in `apps/` or the shared runtime in `sdk/`, then build the applications and ISO:

   ```sh
   make CROSS=x86_64-linux-gnu- apps
   make CROSS=x86_64-linux-gnu- iso
   ```

The Makefile discovers C files directly under `src/` automatically, except `src/stbimg.c`, which has its own build rule. New code should be added to the existing build structure rather than committed generated files from `build/`.

## Tests

The repository includes a host-side authentication test. Run it with:

```sh
make test-auth
```

It uses the host compiler (`HOSTCC`, defaulting to `gcc`) and creates its test executable under the ignored `build/` directory. This test covers the authentication module only; it is not a full kernel or hardware test suite.
